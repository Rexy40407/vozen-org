## Finding

The public site workflow at .github/workflows/pages.yml builds the site correctly, but its publishing path has three avoidable risks:

- permissions: contents: write grants repository write access to the whole job.
- actions/checkout@v4 and actions/setup-node@v4 are mutable tags rather than reviewed commit SHAs.
- The workflow places GITHUB_TOKEN in an authenticated Git remote URL before pushing gh-pages.

Evidence from the audited workflow:

- .github/workflows/pages.yml:19-20 — broad write permission.
- .github/workflows/pages.yml:30-31 — mutable action tags.
- .github/workflows/pages.yml:54-65 — credential-bearing remote setup.
- .github/workflows/pages.yml:81 — direct push to gh-pages.

This is a supply-chain and credential-handling weakness, not evidence that a token has already leaked.

## Scope

In scope:

- .github/workflows/pages.yml
- the repository Pages/environment configuration required by the selected publisher
- existing site build and artifact checks

Out of scope:

- changing application routes or UI behavior
- rotating credentials unless the hardening work proves exposure
- changing the public domain or ownership model without a reviewed decision

## Implementation steps

1. Reconcile plan 001 with the current repository and GitHub Pages settings. Confirm that this repository is the sole publisher of vozen.org, including /account/ and /panel/helper-tracker/. Stop if another workflow still publishes the same domain.
2. Replace the ad-hoc gh-pages push with the official GitHub Pages artifact flow (configure-pages, upload-pages-artifact, and deploy-pages) or document a reviewed equivalent. Resolve the currently supported release SHAs at execution time and pin every action to a full commit SHA with a version comment; do not guess SHAs.
3. Use the minimum permissions required by the selected flow. For the official Pages flow this should be contents: read, pages: write, and id-token: write; remove repository write permission and remove the authenticated Git remote URL.
4. Preserve the existing build gates before artifact upload:
   - npm run docs:build
   - npm run docs:test
   - npm run docs:links
   - npm run docs:a11y
   - npm run site:check
   - helper-panel build and install-artifact checks
5. Keep concurrency cancellation and ensure the uploaded artifact contains CNAME, the account routes, and the helper tracker route.
6. Add a workflow-level check that rejects mutable third-party action references and rejects GITHUB_TOKEN in a shell remote URL.
